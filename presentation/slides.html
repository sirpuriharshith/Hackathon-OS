Context & Objectives

Problem Statement #17 & System Goals

Problem Statement: Develop a system that uses multiple threads to analyze large log files and identify errors, warnings, and suspicious events.

  • I/O Bottlenecks: Traditional fread and fgets double-buffer data through C-library buffers and kernel caches, causing heavy context switching.
  • Concurrency Hazards: Parallel file parsing risks splitting records midway through tokens unless boundaries are newline-aligned. Naive thread locking bottlenecks performance.
  • Security Triage: Server logs contain high-frequency attacks: SQL Injection, XSS, Path Traversal, Recon Probes, and SSH Brute Force.
  • Our Objective: Build a low-level C11 multi-core engine with zero-copy memory mapping, thread arenas, lock-free atomics, and real-time threat intelligence.

Architecture

Multithreaded System Architecture

1. Boundary Partitioning

File partitioned across T threads. Offsets adjust forward to nearest '\n'. Guaranteed zero split records.

2. POSIX Worker Pool

Workers execute in parallel, pinned to CPU cores. Each thread uses an isolated bump-pointer arena.

3. Swappable I/O Modes

1. Memory-Mapped (mmap)
2. Direct Syscalls (read)
3. Standard Buffered (fread)

4. State Synchronization

Per-thread statistics consolidated into GlobalStats using Mutexes, Semaphores, and C11 Atomics.

CO-4 Memory Architecture

Virtual Memory Management & Page Tables

  • 4096-Byte Page Alignment: Thread memory pools are strictly aligned to the OS virtual memory page boundary (4KB), optimizing MMU address translations.
  • Bump-Pointer Memory Arenas: Rather than issuing thousands of lock-heavy malloc() calls, worker threads record alerts in an O(1) bump arena reclaimed in bulk at completion.
  • Process Address Space Inspection: MultiLog-OS programmatically prints its own virtual address segments: Text/Code, Initialized Data, Uninitialized BSS, Heap (brk), and Thread Stacks.
  • Page Fault Telemetry: Queries soft/minor page faults (resolved via page cache) and major page faults using OS kernel counters.
CO-5 File I/O

Boundary-Safe Chunking & Zero-Copy I/O

The Boundary-Safe Chunking Algorithm:

  • Nominal chunk size = File_Size / Thread_Count.
  • For thread i > 0, seeks to nominal offset and scans forward until the first \n. Chunk boundary is set to pos + 1.
  • Thread i-1 ends at this exact byte. Thread i starts at this byte.
  • Result: Zero corrupted lines, zero duplicate records, verified across all thread counts!

mmap Advantage: Maps file pages directly into user space address space. Kernel CPU time drops by 56.4% compared to standard library stream I/O!
